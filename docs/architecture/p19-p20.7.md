# JAMP architecture: P19 → P20.7

This document is the onboarding map for the verified research surface from P19 through P20.7. It is a structural guide, not a claim that every later milestone is closed.

## Evidence-first dependency map

```text
                         OBSERVATION / QUESTION
                                  │
                                  ▼
P19.1  Canonical serialization + content hashing
                                  │
                                  ▼
P19.2  Immutable causal Event DAG
                                  │
                                  ▼
P19.3  Research trajectory / replay projection
                                  │
                                  ▼
P19.4  Research Result + bounded provenance
                                  │
                                  ▼
P20.1  Immutable, content-addressed artifact registry
                                  │
                                  ▼
P20.2  Evidence / outcome projection
                                  │
                                  ▼
P20.3  Provenance binding
                                  │
                                  ▼
P20.4  Hypothesis + Claim verification
                                  │
                                  ▼
P20.5  Evidence-ledger / scoring boundary
                                  │
                                  ▼
P20.6  Search-space / candidate generation boundary
                                  │
                                  ▼
P20.7  Deterministic research planning / experiment selection
                                  │
                                  ▼
                         EXPLICIT NEXT EXPERIMENT
```

The arrows describe information flow and contract dependency, not permission to mutate lower layers.

## Layer contracts

| Layer | Role | Must preserve |
|---|---|---|
| P19.1 | canonical representation | byte-stable serialization and deterministic hashes |
| P19.2 | causal core | immutable events, causal order, integrity |
| P19.3 | replay | deterministic reconstruction from recorded state/trajectory |
| P19.4 | result projection | content-addressed result identity and bounded provenance |
| P20.1 | artifact registry | immutable artifact identity and lineage |
| P20.2 | evidence projection | explicit evidence objects rather than hidden state |
| P20.3 | provenance | links from claims/evidence to their source objects |
| P20.4 | verification | distinguish verified claims from hypotheses |
| P20.5 | scoring | evidence-bounded evaluation; no retroactive history mutation |
| P20.6 | search boundary | candidate generation separated from causal history |
| P20.7 | planning | deterministic experiment designs; never predict empirical outcomes |

## Boundary rules

1. Lower layers do not import higher-level search or policy decisions.
2. `jamp.research` remains isolated from `jamp.domain` where the existing contracts require it.
3. Network access is not part of the deterministic research-core contract.
4. Runtime identity, wall-clock metadata, filesystem order, and environment noise must not silently enter content-addressed identity.
5. A plan is not an observation; a hypothesis is not a result; a result is not a proof.
6. A workflow run is evidence only when its exact target revision and acceptance contract are known.
7. Causal ablation removes specified mechanisms and records what happened; it does not assume the expected outcome.

## How a new contributor should read the code

Start with the contract test for the milestone, then the implementation, then its diagnostic workflow. For P19, the principal modules are `src/jamp/research/canonical.py`, `causal.py`, `replay.py`, and `result.py`. For P20.1 and P20.7, inspect `registry.py` and `planning.py` together with their acceptance tests and diagnostic workflows.

The repository also contains later P20/P21/P22/P23/P24 work. Those later surfaces can preserve or extend the P19/P20 compatibility contracts; they must not be used to retroactively rewrite what P19/P20.7 evidence meant at the time it was produced.

## Gate semantics

`SPECIFIED → IMPLEMENTED → EXECUTED → EVIDENCED → VERIFIED → CLOSED` is the canonical research lifecycle. A milestone that is merely implemented or locally tested is not automatically VERIFIED.

## Extension boundary

Plugins and custom engines sit above this map. They may submit observations/candidates through public contracts and consume verified results, but they must not mutate the causal DAG, bypass provenance, or replace content-addressing with runtime identity.
