- The earliest available README describes JAMP as **“Causal Experimental Architecture for Machine Discovery.”** It frames the system as an experimental architecture for machine-discovery systems whose search results are reproducible, causally ordered, integrity-verifiable and replayable.
- The same README lists these principles: Causal Event DAG, deterministic search, replay/time travel, policy learning, task isolation, controlled knowledge transfer, causal ablation and evidence-first milestone validation.
- The research protocol says the system should preserve not only the final result but the path by which it was obtained. It explicitly names observations, questions, hypotheses, actions, failed attempts, causal relationships and state transitions as parts of a reconstructable research artifact. It also says not to fit a mechanism retrospectively to a known answer.
- The architecture README separates causal core, evaluation, pattern index, policy adaptation, search boundary, experiment registry, task isolation, controlled transfer and ablation. It states that reproducibility and auditability are part of the mechanism, not documentation added afterward.

## 2. Inferred / oral-history account

The project lead recalls that on **September 6, 2026**, the starting question was why humanity had not solved major longstanding problems despite having advanced technologies and AI. The first concrete exploration reportedly used the Rubik's Cube, followed by trying different approaches; JAMP emerged through that exploration.

This account is recorded as **USER RECOLLECTION / ORAL HISTORY**, not as repository-verified history. No September 6 transcript, note, commit or source artifact has yet been located in the accessible repository evidence.

A possible conceptual connection is that a Rubik's Cube has a large state space, constrained legal moves and an independently checkable solved state. This can illustrate a separation between finding a candidate solution and checking whether it satisfies the goal. That connection is an interpretation; the available artifacts do not establish that it was the actual mechanism or reasoning that led to JAMP.

## 4. Why the distinction matters

The earliest repository evidence supports a machine-discovery and reproducible-experiment foundation. Later Trust Layer capabilities may be an evolution or application of that foundation; this document does not assert that they were the original purpose.

Commercial products must not redefine the project's mission merely because one use case is easier to sell. Any mission or architecture update should be grounded in the historical artifacts and explicit decisions, with unresolved origin questions kept visible.
