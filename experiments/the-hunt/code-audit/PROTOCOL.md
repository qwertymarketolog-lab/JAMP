# The Hunt: Code Audit & Supply Chain

## Objective
To measure the effectiveness of JAMP's Evidence Engine in detecting "Hallucinated Packages" (slopsquatting) and fake APIs generated by LLMs, compared to a standard LLM generation without verification.

## Hypothesis
Standard LLMs frequently hallucinate non-existent Python libraries or misrepresent their APIs. 
- **Baseline:** LLM generates code blindly.
- **JAMP:** LLM generates code + JAMP intercepts, checks PyPI existence, and validates provenance.

## Dataset
- 50 structured prompts requiring specific but obscure libraries (e.g., "Write a script to parse a specialized financial XML format using [fake_library]").
- 50 standard prompts (e.g., "Write a script to read a CSV").

## Metrics
1. **Hallucination Catch Rate:** % of fake packages/APIs caught by JAMP.
2. **False Positive Rate:** % of real packages incorrectly blocked by JAMP.
3. **Latency Overhead:** Time added by JAMP verification.
4. **Cost:** Token cost difference between Baseline and JAMP.

## Protocol Steps
1. Execute 100 prompts against the baseline LLM.
2. Run static analysis (AST parsing) on the output.
3. Execute 100 prompts with JAMP interception.
4. Manually review discrepancies.
5. Log results in `RESULTS.md`.
